# Groq planner reliability investigation — 2026-07-27

## Symptom

`scripts/pregenerate_showcases.py` failed while creating its first campaign with
Groq HTTP 400 `json_validate_failed`. The provider sometimes reported an empty
`failed_generation`, and an earlier response reported that its completion budget
ended before a valid document could be generated.

## Root cause

The failure occurred at the external structured-output boundary, before the
application received a model response. The previous planner mixed three
contracts:

- a generated Pydantic schema sent to Groq strict mode;
- a prompt which described `vo` as optional even though strict mode made it
  required; and
- application-owned zero-based beat indexes generated by the model.

The strict decoder could intermittently fail for that request shape, and the
planner had no same-contract model failover. A live reproduction also showed a
valid structured model response using one-based indexes, which the application
correctly rejected. The latter is a deterministic responsibility and should not
belong to an LLM.

## Fix

- The Groq planner now uses a small hand-authored strict JSON Schema: all
  fields are required, all objects are closed, and `vo` is a required nullable
  string. This is the contract documented by Groq for strict output.
- The model produces an ordered list of beat content only. The server assigns
  stable zero-based `Beat.index` values, eliminating a semantic LLM failure
  mode.
- `openai/gpt-oss-20b` remains the primary planner. After its bounded retry
  budget is exhausted for a transient provider error, the app fails over to
  `openai/gpt-oss-120b`, using the identical strict schema rather than a loose
  JSON or text fallback.
- The Qwen vision judge uses Groq's supported JSON Object mode plus local score
  validation; it does not pretend to support strict JSON Schema.
- Local Pydantic validation remains the final application trust boundary.

## Evidence

- Live strict-schema requests succeeded against both GPT-OSS 20B and GPT-OSS
  120B.
- A final live `plan_beats(..., beat_count=4)` call returned four beats with
  indexes `[0, 1, 2, 3]` and valid required fields.
- Regression tests cover strict-schema payload shape, provider retries,
  strict-model failover, local schema rejection, deterministic index assignment,
  and vision JSON Object mode.
- `python -m unittest discover -s tests -v`: 46 passing tests.
- `python -m ruff check .`: passed.

DONE. The remaining ffmpeg `drawtext` prerequisite is unrelated to this
